## 修复 IDEA 报 "Error reading file gateway-module/pom.xml"

**现象**：IDEA 加载该 Maven 项目时报错，指向 `apps/backend/gateway-module/pom.xml`。

**根因**：项目 pom 本身完全合法（UTF-8/无 BOM/XML 合法）。真实原因是本地 Maven 仓库 `D:\Developer\Maven\local-repertory` 中的
`org/springframework/boot/spring-boot-dependencies/2.3.2.RELEASE/spring-boot-dependencies-2.3.2.RELEASE.pom`
被缓存成了 JFrog 的「503 Maintenance」HTML 页面（158720 字节）。IDEA 解析父链（spring-boot-starter-parent → spring-boot-dependencies）时撞上它，错误被归到子模块 pom 上。
这是历史残留：当初用过 JFrog 镜像，503 页被当成 pom 存下；现在 settings.xml 已改用阿里云，`<mirrorOf>*</mirrorOf>`。

**排查关键**：`mvn -o -q -f gateway-module/pom.xml validate` 打印出真实的 ModelParseException，比 IDEA 的报错信息准。
全仓库扫描 2154 个 .pom，仅此 1 个损坏。

**修复**：删除该损坏 pom + 同目录 `.pom.sha1` + `_remote.repositories`，再 `mvn -U -f gateway-module/pom.xml validate` 从阿里云重新下载。
新文件为合法 XML（121530 字节），`mvn -o -q validate` 整个 backend 模块树通过。

**结论 / 通用经验**：IDEA 报 "Error reading file X/pom.xml" 时，先别改项目 pom，用 `mvn validate` 看真实报错——多半是本地仓库里某个上游依赖的 pom 损坏（HTML 错误页缓存）。

## 前端启动验证（Node 22 环境）

- 环境：Node v22.22.2 / npm 10.9.7，registry=淘宝镜像；`apps/frontend` 初始无 node_modules。
- **安装必须加 `npm ci --legacy-peer-deps`**：直接 `npm ci` 会因 `eslint-plugin-react-hooks` 版本冲突（1.5.0 vs ^1.6.0）报 ERESOLVE 失败。这是 UmiJS 2 老项目在 npm 7+ 的标准问题，非代码错误。2801 包 / 3 分钟，仅 deprecation 警告。
- `npm run dev` 启动成功（脚本已带 `NODE_OPTIONS=--openssl-legacy-provider`，绕开 Node 17+ 的 OpenSSL 3 问题）：编译 14.8s，服务 `http://localhost:8000/`。
- 运行时验证：首页 200、`/umi.js` 4.9MB 200、`/umi.css` 584KB 200、`/api/users` 返回扁平 `{list:[...]}`（印证契约文档 §3 的前端期望），无 stderr 错误。
- 结论：前端基线代码本身可正常启动运行；`--legacy-peer-deps` 是安装前提，写文档/交接时要带上。
