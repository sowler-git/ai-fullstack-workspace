# shells/ — 多端壳工程容器

小程序与 APP 的壳工程位置。壳只做**平台容器 + Webview 承载 + 原生桥接**，业务逻辑一律加载 `h5/`。

## 状态

**占位目录，暂无实现。** 本层只保留本 README；各端子目录在对应端立项时才创建。

## 规划中的端

| 端 | 承载方式 | 关键约束（立项前必须处理） |
| --- | --- | --- |
| 微信 | Webview 加载 H5 | 企业主体方可使用 `web-view`；需配置业务域名白名单与校验文件；纯套壳违反运营规范，会被拒审，需提供原生价值 |
| 飞书 | Webview 加载 H5 | 企业自建应用；需处理飞书登录态注入与免登；容器 API 与微信不通用 |
| 钉钉 | Webview 加载 H5 | 企业内部应用；需处理钉钉 JSAPI 鉴权与免登；域名白名单约束 |
| Android | Webview 或 Capacitor 壳 | 应用商店对纯套壳有最小功能要求；需原生桥接层；注意 Webview 版本差异 |
| iOS | WKWebView 或 Capacitor 壳 | App Store 审核指南 4.2 条限制纯套壳；需原生能力与隐私清单 |

## 统一原则

1. **业务逻辑不进壳**。壳里只写容器配置、启动页、桥接实现、平台适配。
2. 桥接接口统一定义在 `shared/`，各端各自实现，接口签名不得分叉。
3. 认证不在壳里做完整登录流程——壳负责获取平台身份，按约定方式注入 `h5/`。
4. 每个端是独立工程，独立构建与发布，不共享构建产物。

## 何时创建子目录

每个端只有在以下条件全部满足时才建目录：

1. `specs/changes/` 中有该端的已批准变更记录；
2. 该端平台资质就绪（如小程序企业主体、域名备案）；
3. 桥接协议已在 `shared/` 定义；
4. 已含该端审核风险的应对方案（不能是纯套壳）。

在此之前，本目录保持只有 README 的状态。
