# shared/ — 跨端共享资产

存放 `web/`、`h5/`、`shells/` 各端之间需要保持一致、但不属于任何单一端的资产。

## 状态

**占位目录，暂无实现。** 仅保留本 README 标记约定位置。

## 收什么

- **接口契约**：后端 API 的请求/响应类型定义、错误码映射、与 `docs/frontend-backend-contract.md` 对应的机器可读描述。
- **桥接协议**：壳工程与 `h5/` 之间的 Native Bridge 接口签名（登录态注入、分享、推送、支付等），各端按签名各自实现。
- **纯逻辑工具**：不依赖任何 UI 框架或平台 SDK 的工具函数。

## 不收什么

- 不收 UI 组件——各端视觉体系不同，强共享会导致耦合。
- 不收构建配置——各端独立构建。
- 不收平台 SDK 适配代码——那是各壳工程自己的职责。
- 不收 `admin/` 的任何东西——后台管理系统与多端业务端是隔离的，不共享资产。

## 使用约定

1. `shared/` 的内容变更影响所有端，必须走 `specs/changes/` 的变更记录与 ADR。
2. 各端以只读方式消费；需要扩展时先在 `shared/` 达成契约，再各端适配。
3. 保持零 UI 框架依赖，确保任意技术栈的端都能引用。

## 何时填代码

等第一个跨端需求真正出现时（例如 `h5/` 与首个壳工程要建立桥接），才在本目录创建文件并配套 ADR。在此之前保持只有 README 的状态。
